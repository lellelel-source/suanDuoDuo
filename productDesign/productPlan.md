# 算多多 - 算力撮合交易平台产品方案

## 1. 项目概述
本平台定位为专业的**算力撮合交易平台**，旨在连接算力供应商与需求方，提供包括公有云算力、IDC 裸金属算力、模型 API 调用及在线 LLM 对话等多种形态的算力服务。平台兼顾个人开发者与企业客户，需构建一套能够同时支持 B 端复杂采购流程与 C 端便捷消费体验的混合架构。

## 2. 核心业务矩阵

| 业务板块 | 目标客户 | 产品形态 | 支付方式 | 核心特性 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 云算力** | 企业 | 阿里云/腾讯云等公有云资源 | 浦发 B2 (企业网银) | 仅支持企业实名认证账户购买，合规票据 |
| **2. IDC 算力** | 企业 | 托管/租用裸金属机柜、GPU 服务器 | 浦发 B2 (企业网银) | 大额资金流转，合同与线下交付流程协同 |
| **3. API 服务** | 企业 & 个人 | LLM 模型接口 (基于 NewAPI) | 支付宝/微信 (个人)<br>浦发 B2 (企业) | 支持余额充值、按量计费，企业与个人账户隔离 |
| **4. 在线 LLM 聊天** | 个人 (会员) | SaaS 聊天室 | 支付宝/微信 | 订阅制/按次付费，仅面向 C 端用户 |

## 3. 账户与身份体系设计 (Identity & Access Management)

为解决 B/C 端业务共存的问题，且避免用户管理多个账号，采用 **“统一通行证 + 多工作空间 (One Passport, Multiple Workspaces)”** 的设计架构。

### 3.1 核心概念模型
*   **User (通行证)**: 用户的唯一登录凭证（手机号/邮箱），代表“自然人”。
*   **Identity/Profile (身份)**: 用户在特定环境下的角色。
*   **Workspace (工作空间)**: 数据与资金物理隔离的操作环境。

### 3.2 工作空间隔离机制
平台仅存在两类标准工作空间，用户登录后可通过顶部导航栏进行切换。

#### A. 个人空间 (Personal Workspace)
*   **适用场景**: 在线 LLM 聊天、个人 API 开发调试。
*   **开通方式**: 注册即默认开通。
*   **支付限制**: 仅支持微信/支付宝，**屏蔽**浦发 B2 支付。
*   **功能限制**: 无法查看或购买云算力及 IDC 算力产品。

#### B. 企业空间 (Enterprise Workspace)
*   **适用场景**: 企业采购云算力、IDC 资源、企业级 API 接入。
*   **开通方式**: 需提交营业执照进行企业认证 (KYB)。
*   **成员管理**: 支持邀请制。不仅有 Owner，还有管理员、财务、普通成员等角色。
*   **支付限制**: 仅支持浦发 B2 支付 (或企业余额)，**屏蔽**个人支付渠道，确保资金合规。
*   **UI 区分**: 建议采用深色/商务风格主题，顶部常驻显示“当前企业：[企业名称]”，强化 B 端属性。

### 3.3 数据库模型设计 (ER 简述)
*   `users`: 基础用户表 (id, phone, password)
*   `enterprises`: 企业主体表 (id, name, tax_id, b2_account_info)
*   `enterprise_members`: 成员关联表 (user_id, enterprise_id, role, status)
*   `current_context`: 记录用户最后一次停留的空间，下次登录自动跳转。

## 4. 资金与支付体系 (Payment & Settlement)

资金安全与合规是撮合平台的生命线，需建立严格的**资金隔离墙**。

### 4.1 钱包系统 (Wallet System)
每个工作空间拥有独立的钱包，**余额互不通用**。
*   **个人钱包**: 关联 `user_id`。充值来源：微信/支付宝。用途：消费 Chat 会员、个人 API 额度。
*   **企业钱包**: 关联 `enterprise_id`。充值来源：对公转账、浦发 B2。用途：支付云资源/IDC 账单、企业 API 额度。

### 4.2 智能支付路由 (Payment Router)
收银台 (Checkout) 需根据**当前商品属性**和**当前工作空间**动态渲染支付方式。

| 当前空间 | 商品类型 | 允许的支付方式 | 异常处理 |
| :--- | :--- | :--- | :--- |
| **个人** | LLM 会员 / 个人 API | 微信、支付宝 | - |
| **个人** | IDC / 云算力 | - | **禁止下单**，提示“请切换至企业账号” |
| **企业** | IDC / 云算力 | 浦发 B2、企业余额 | - |
| **企业** | 企业 API | 浦发 B2、企业余额 | - |

## 5. NewAPI (Open Source) 集成方案

计划采用开源项目 **NewAPI (OneAPI)** 作为底层的模型网关与计费引擎，但不直接暴露给终端用户。

### 5.1 托管模式 (Shadow Accounts)
采用“影子账户”策略，实现平台账户与 NewAPI 账户的隐式绑定。

1.  **账号同步**:
    *   用户在个人空间激活 API 服务时 -> 后端自动在 NewAPI 创建一个 `User` (Group: Personal)。
    *   企业在企业空间激活 API 服务时 -> 后端自动在 NewAPI 创建一个 `User` (Group: Enterprise)。
2.  **额度管理 (Quota)**:
    *   NewAPI 仅作为**计费消耗记录器**。
    *   **充值逻辑**: 用户在平台侧充值 -> 平台数据库余额增加 -> (划转时) -> 调用 NewAPI 接口为对应影子账号加额度。
    *   或者采用**实时扣费模式**: 平台余额为主，NewAPI 设置无限额度，仅通过 NewAPI Logs 获取消耗日志，并在平台侧异步扣除余额（适合高并发场景）。

### 5.2 Key 的管理
*   UI 层重写令牌管理页面。
*   **隔离展示**:
    *   个人空间仅展示归属于个人的 Access Key。
    *   企业空间仅展示归属于企业的 Access Key。
*   **离职管控**: 当员工被移除出企业空间，其在该空间下看到的企业 Key 不需要失效（Key 归属企业），但该员工将立刻失去获取和查看这些 Key 的权限。

## 6. 用户交互流程 (User Journey)

### 场景：企业采购员购买算力
1.  **登录**: 使用个人手机号登录平台。
2.  **切换**: 点击右上角头像，选择“切换工作空间” -> 选择目标企业“杭州XX科技有限公司”。
3.  **浏览**: 页面刷新，进入企业版界面，看到 IDC 资源列表。
4.  **下单**: 提交算力采购订单。
5.  **支付**: 跳转浦发银行 B2B 支付网关完成付款。
6.  **交付**: 等待平台/供应商交付资源。

### 场景：开发者使用 API
1.  **登录**: 个人手机号登录。
2.  **默认**: 默认进入“个人空间”。
3.  **充值**: 点击钱包，微信扫码充值 50 元。
4.  **令牌**: 点击“开发者中心”，生成一个新的 API Key。
5.  **调用**: 使用该 Key 在本地代码中调用 NewAPI 接口，扣除个人余额。
